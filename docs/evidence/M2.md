The Vue-specific additions exist because Vue changes the question. A React component is a
function and so is rejected by any prototype check; a Vue component is a *plain object* and
would pass one. It is correctly rejected because it carries function properties that the
recursive walk finds — asserted explicitly so that reasoning cannot silently rot. Likewise
`markRaw`: a component in reactive state must come back as the same object, not a Proxy.

## Layout compatibility

10 fixtures in `test/fixtures/rdd-6.2.0/`, **eight produced by rdd 6.2.0 itself** — its own
actions, its own `saveLayout()` — and two hand-written legacy shapes it can no longer produce
but must still read (pre-`anchor` `sticky*` flags, and a pre-`activePanelId` layout).

anchors, `maximized`, z-order, `previousState`, `lastLeafId`, `lastFloatingRect`, `props`,

`sticky*` migration produces a logical anchor; malformed input is rejected rather than
half-applied. Writing (the full round-trip) is gated when `saveLayout()` lands in M6.

## Gate improvements

**`api-surface` was measuring the wrong thing.** It tried to import the TypeScript source,
silently fell back to `dist` when that failed, and reported the surface of a *stale build* —
7 real exports read as 1. Now it reads the built output deliberately, **refuses to run
against a stale build** (comparing mtimes against `src/`), and covers the type surface too by
parsing `dist/index.d.ts`: for a TypeScript library, types are half the API, and a type-only
export is invisible at runtime. Surface is now 7 runtime + 26 type exports.

A new self-test case (`api-surface refuses a stale build`) guards that fix; all **7** gate
rules remain proven non-vacuous.
