The last milestone. `/demo` ported as **24 source files**: sixteen panel kinds, a shell, two

## What the demo is for

Three things, and the second two are why it earns a gate of its own:

1. **It shows the library off.** Sixteen panels, every placement, every piece of chrome.
2. **It is the integration test.** The only place the library meets Monaco, Leaflet, a
   `unified` markdown pipeline, six locales and every one of its own components *at once* — and
   a library's integration failures surface as a console error in an application long before
   they surface in a unit test. The browser gate treats any console error as a failure, with
   the listener armed before the first navigation.
3. **It is where the manual's examples run**, which ADR 0013 asked for so the documentation
   cannot drift from the code.

32 steps, seven screenshots, and every assertion the plan named:

Two of those are worth drawing out.

**`active is visible`** re-checks the invariant the whole port is built on, at the end of the
hardest path there is: save sixteen panels, reload the page, restore. It does not merely
compare ids — it walks the restored tree and asserts the active panel is not minimised and is
the *selected tab of its own leaf*, not merely present in it. That is exactly what rdd got
wrong (divergence D2).

**`survival: terminal 6 lines`** is the zero-unmount guarantee, end to end. The terminal
appends a line every 1.2 seconds and starts with three; a panel re-created at any point in
those 32 steps would show three. It was docked, split, floated, anchored, maximised,
minimised, restored, saved and reloaded — and kept counting.

## Dependencies, per ADR 0013

Kept, because they are framework-agnostic and mount into a plain element: **`monaco-editor`**
(directly — `@monaco-editor/react` is a wrapper for React's lifecycle, replaced by a 90-line
composable), **`leaflet`**, and the markdown pipeline **unchanged** (`remark-gfm`,
`remark-math`, `rehype-katex`, `rehype-highlight`, `rehype-raw`, `rehype-slug` — `unified`
plugins, not React components, so only the renderer differed).

Swapped: `react-bootstrap` and its submenu add-on for the demo's own `dd-` markup, and
`react-intl` for a **twelve-line formatter**. That last one is the more interesting: the
library's entire i18n surface is `(descriptor) => string`, so the six message tables port as
plain data and the "integration" is a closure over a `ref`. The gate asserts no React
dependency has crept back, and that the library itself still has **zero runtime
dependencies** with Vue as its only peer.

## The demo does not leak into the library

rdd published its demo's `sb-*` utility classes in the *library's* stylesheet: every consumer
downloaded styling for an application they never saw. ADR 0008 closes it and the M14 gate
keeps it closed, four ways — no `dd-` class in `src/index.css`, no `demo` entry in the
package's `files`, no global `vdd-` selector in the demo's stylesheet, and no demo file
reaching into `src/` instead of importing the package by name.

That last one matters for a second reason: the demo imports `vue-dockable-desktop` and
`vue-dockable-desktop/styles.css` exactly as the manual tells a consumer to, with an alias
pointing at the repository. So it reads like an application while exercising the source, and
`npm run demo:build` — now a step in the standing gate — proves the same code builds the way a
consumer would bundle it.

## Findings

**Leaflet paints over the panel overlay.** Leaflet gives its own map panes `z-index: 400`,
which is higher than a floating widget's, so the legend and the status strip were in the DOM,
laid out correctly, and invisible. The library cannot prevent that — it does not know what a
panel renders — so the fix is `isolation: isolate` on the demo's own map element. Worth a
manual section rather than a silent one-liner, and chapter 7 now carries it: *any* panel
content with its own high z-indexes needs a stacking context.

**A layout chain that silently did nothing.** The workspace filled only 70% of the window
because the wrapper inside the sidebar's slot used `flex: 1` — and `.vdd-sidebar-main` is a
block, not a flex container, so it had no effect at all. Measured rather than guessed at, then
fixed with a real height.

**A ref read through the template's auto-unwrapping.** `locale` is a `ref` injected into
`setup`, so the template unwraps it — and `v-model="locale.value"` was reading `.value` off a
plain string, binding the language selector to `undefined`. The kind of thing that looks
right and renders empty.

**`ws.loadLayout(saved)` called twice** in one expression, once in the condition and once in
the message. It applied the whole layout twice.

**Keyless tiles.** CartoDB's basemaps now require an API key, and the demo's map was rendering
"API KEY REQUIRED" across every tile. Switched to OpenStreetMap's standard tiles, with the
dark look done as a CSS filter on the tile pane rather than a second provider — one source, no
token, and it follows the workspace's colour scheme.

## Gate harness lessons, again

The browser gate's first run **hung with no output at all**, and its second **crashed** rather
than reporting. Both were the gate's own fault, and both are now guarded:

- `page.evaluate` awaits whatever the function returns, and `requestClosePanel` on a dirty
  panel returns a promise that settles only once the user answers. Returning it waited
  forever. `void` starts the close and lets the walkthrough answer the dialog, which was the
  point of the step.
- An unexpected navigation surfaced as "Execution context was destroyed", thrown from whatever
  ran *next* rather than from the click that caused it. A `framenavigated` listener now names
  the step, and reading state can never be what ends the run.

Two more failures were the gate mis-modelling the application rather than the library: a
modal's curtain covers the panel that opened it (so the toast had to be raised before the
modal, not after), and clicking "save" focuses the Control Center (so a state snapshot taken
before the save step was already stale — the assertion now compares against the *saved
payload*, which is what a restore actually has to reproduce).

## The runner learned a pragma

Browser gates need an app served, and until now that was always the playground. M14 drives the
demo, on a different port. Rather than a lookup table in the runner, a gate declares its own
app on any line of itself:

```js
// gate:app demo
```

The runner reads it and serves `demo/` on :5190 instead of `playground/` on :5188, with a
90-second wait because Monaco makes the first cold start slow. Adding a browser gate no longer
means editing the runner, which integrity rule 2 asks me not to do.

`npm run gate:selftest`: **73** rules, all non-vacuous — six of them M14's, including rdd's
actual leak (a demo class in the published stylesheet) and the two that would undo the
library's dependency promise.
