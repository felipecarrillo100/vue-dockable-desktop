## What changed

react-dockable-desktop 7.2.0's skin branding, ported ([0017](../decisions/0017-brand-variables.md)).
angular-dockable-desktop 1.1.0 had already ported it, and its stylesheet descends from this one,
so its conversion was replayed onto `src/index.css` after the prefix swap: 45 of 51 hunks applied
as-is. The 6 that did not were font rules that vdd 1.2.0 had already converted to
`var(--vdd-font-family)`; only the `:root` declaration needed a hand edit.

- `src/index.css`: 14 `--vdd-accent-color` declarations read `var(--vdd-brand-accent, <skin colour>)`
  (13 converted, 1 new in `[data-color-scheme="light"]`, `#0066cc`); 142 accent tints and stale
  accent-family literals became `var(--vdd-accent-color)` or
  `color-mix(in srgb, var(--vdd-accent-color) N%, transparent)`; 2 on-accent rules read
  `--vdd-brand-on-accent`; `:root` declares `--vdd-font-family: var(--vdd-skin-font-family, …)`,
  and six skins set `--vdd-skin-font-family`.
- **One fix found by the gate:** `.vdd-toolbar-btn` and `.vdd-sidebar-tab-btn` rendered in the
  browser's button font (Arial) whatever `--vdd-font-family` said, a brand font included: a
  `<button>` does not inherit a font. rdd fixed this in 6.4.0 with
  `:where(button, input, select, textarea)[class*="rdd-"] { font-family: inherit }`, which vdd
  (at 6.3.1 parity) never had. Ported, with a unit test.
- Playground: `?skin=`, `?cs=light`, `?ba=` / `?bon=`, `?anim=0`.
- Demo: the `mono` skin is brandable.
- Docs: theming chapter (Brand your app, Skin fonts, brandable skins, token reference), chapter 1,
  chapter 12, README, CHANGELOG 1.3.0, ADR 0017, PARITY.md, this plan. Version 1.3.0.

## Browser gate (`scripts/gates/browser/m15.mjs`)

The port of ndd's M16 browser gate, check for check, as a standalone Playwright script like vdd's
other gates.

- **Baseline:** captured from the 1.2.0 stylesheet before any edit, every scene twice (the two
  captures agreed in all 14), into `scripts/gates/browser/fixtures/m15-branding-baseline.json`.
  A scene missing any of 12 pieces of chrome refuses to capture (proven by planting a missing
  one). Against the unchanged 1.2.0 stylesheet the gate reported 0 differences in all 14 scenes,
  and every brand, on-accent and font check failed, as it should.
- **No brand:** every scene matches the baseline except the intended fixes (entries changed,
  dark / light: vscode 0 / 23, macos 0 / 1, chrome 43 / 72, slate 26 / 84, nord 43 / 84,
  obsidian 55 / 93, tokyo 147 / 176). Identical to ndd's M16 except tokyo (ndd 165 / 194,
  different chrome in the scene); 0 unintended.
- **Red brand `#e4002b`:** 0 traces of any original accent in all 14 scenes; 134–212 red uses per
  scene.
- **On-accent:** yellow `#facc15` with `#1a1a1a` gives `rgb(26, 26, 26)` text on
  `rgb(250, 204, 21)`, in dark and in light.
- **Fonts:** each skin's stack on all 20 chrome roots (teleported ones included), the library
  stack for `obsidian` and a custom skin; a consumer `:root` font wins in all 7 skins.
- **Control** (`--control`: nord redeclares its accent and `--vdd-font-family`): rejected.
